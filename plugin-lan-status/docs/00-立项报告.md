# dsh-lan-status · 立项报告（00）

> 状态：MVP 已实现，待四节点部署与真机验证  
> 日期：2026-11-20  
> 定位：LAN 多节点 DSH 实验环境的**只读**状态面板，不参与调度、不写 DSH。

## 1. 问题

四台机器上的 DSH 是彼此独立的 `dsh web` 进程：

- 入口 URL 各带一次性 launch token，无法直接拼一个“总入口”；
- 每个节点有哪些活会话、哪些任务在跑，只能逐个节点看；
- 协调者 dsh-a 的任务台账在 `~/.dsh-lan-scheduler/state.json`，其他节点看不到；
- 用户需要一个页面回答“现在四台机器整体是什么状态”。

已有 `dsh-interconnect` 只传消息，`dsh-lan-scheduler` 只排队/派活，两者都不提供**跨节点只读视图**。

## 2. 目标 / 非目标

### 目标

1. 单页展示：节点属性（主机/OS/DSH 版本/角色/入口）、在线状态与延迟、会话、运行中任务、最近终态任务。
2. 每节点可独立部署；agent 只暴露 `/self`，coordinator 聚合。
3. 只读：不写 DSH 状态、不写调度台账、不读消息正文、不持有 token。
4. 不依赖 DSH client 半：独立 `node:http` 服务，避免 `ctx.remote`/client assembly 改造。
5. 可在 Windows（.24）与 Linux（.21/.23）混合环境运行。

### 非目标

- 不做鉴权/账号体系；假定可信 LAN。
- 不做历史存储/趋势图/告警。
- 不做任务控制（提交/取消）——那是 `sched_*` 的职责。
- 不做文件传输/DAG/多协调者。
- 不拼接 launch token，不代替用户打开各节点入口。

## 3. 架构

```
浏览器 ──GET /status──► dsh-a :3091（coordinator）
                         │  GET /self
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     dsh-b :3091    dsh-c :3091    dsh-d :3091
```

- 每个节点：`node:http` + `node:os` + `ctx.agents.list()`。
- 协调者额外：读 `schedulerStateFile`（默认 `~/.dsh-lan-scheduler/state.json`）。
- 本地节点不递归：`instanceId` 等于 self 时直接复用 `self`，远端才 `agentUrl/self`。
- 聚合缓存 2s；单节点超时 2500ms；离线节点显示 `error`，不阻塞整页。

### `/self`

```json
{
  "ok": true,
  "generatedAt": "ISO",
  "node": {
    "instanceId": "dsh-a", "label": "dsh-a", "role": "coordinator",
    "origin": "http://192.168.3.23:3081",
    "agentUrl": "http://192.168.3.23:3091",
    "hostname": "...", "platform": "linux", "arch": "x64",
    "osRelease": "...", "nodeVersion": "v24.22.3", "dshVersion": "0.2.2-rc.3",
    "pid": 1234, "uptimeSec": 42, "startedAt": "ISO"
  },
  "sessions": [{ "sessionId": "...", "title": "...|null", "status": "...", "cwd": "..." }],
  "tasks": {
    "stateFile": "...", "seq": 23, "total": 10,
    "running": [{ "id": "...", "title": "...", "status": "running", "workerId": "w-2", "instanceId": "dsh-a", "attempts": 1, "createdAt": "ISO", "lastError": null, "summary": null }],
    "recent": [{ "...": "终态任务，最近 12 条" }]
  }
}
```

### `/status`

```json
{
  "ok": true, "generatedAt": "ISO", "coordinator": "dsh-a",
  "summary": { "nodes": 4, "online": 4, "offline": 0, "sessions": 5, "runningTasks": 1 },
  "nodes": [{ "...": "node + online/latencyMs/error + sessions + tasks" }],
  "sessions": [{ "...": "session + instanceId" }],
  "tasks": { "running": [{ "...": "task + coordinator" }], "recent": [] }
}
```

字段约定：

- `tasks.running` 状态闭集 `queued|dispatching|running`；`tasks.recent` 只收 `succeeded|failed|cancelled`。
- 任务标题截断 120 字，summary/lastError 截断 240 字；不返回 prompt。
- 会话不返回消息内容；标题取不到为 `null`。

## 5. 安全

| 面 | 决定 |
|---|---|
| 认证 | 无；只监听可信 LAN，默认 `0.0.0.0:3091` |
| 凭据 | 不读 `DSH_INTERCONNECT_TOKEN`、provider key、launch token |
| 入口 | `origin` 只是 base URL；用户点开仍需该节点 token |
| 写面 | 无写路由；不注册工具；不改 DSH 状态 |
| 会话 | 只列 id/title/status/cwd，不读正文 |
| 任务 | 只读协调者台账；摘要可能含业务信息，台账按 600/ACL 保护 |
| 传输 | 明文 HTTP；按用户要求不使用 SSH 隧道，限可信网段 |

## 6. 验收

- 单测 9/9：任务/会话归一化、协调者 vs agent、离线聚合、HTTP 路由、404/405、HTML 自包含。
- 四节点真机（2026-11-20 已执行）：
  1. 各节点 `/health` 返回自己的 `instanceId/role`：A/B/C/D 均 200。
  2. 各节点 `/self` 的 `sessions` 为**当前活会话**；重启后无活会话时为空是真实结果，不是失败。
  3. 协调者 `/status` 的 `summary.nodes=4`、`online=4`。
  4. 浏览器入口 `http://192.168.3.23:3091/`：HTML 200、8783 bytes，节点/任务/会话表由前端 `/status` 渲染。
  5. 离线降级逻辑由 `tests/status.test.mjs` 的离线节点用例覆盖；真机停节点未再单独演练。
- 只读验证：`/health`、`/self`、`/status` 不接收写方法；部署前后 dsh-a 台账 `seq` 由 40 保持不变，没有新 journal 事件。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| `ctx.agents.list()` 字段随宿主版本变化 | 全部读取包 try/catch；取不到会话/标题就降级，不让路由 500 |
| 端口 3091 冲突 | `/health` 必须实测；启动失败只 logger.error，部署检查不能只看 systemd active |
| 同机 A/B 台账混淆 | agent 不读台账；只有 coordinator 读自己的 `schedulerStateFile` |
| 面板被公网访问 | 文档明确只限 LAN；需要时加防火墙白名单/反代认证 |
| 任务摘要泄漏 | 台账 600/ACL；面板不返回 prompt；摘要截断 |
| 入口 token 泄漏 | 配置/页面只放 base URL；不读日志 token |

## 8. 决策

选择**独立 HTTP 服务**而非 DSH client 面板：

- client 面板要改 `ctx.remote` 可用的 namespace/assembly，或把自定义 host 服务接到 client graph；本任务只是只读聚合，不值得引入 client graph 的构建/重启成本。
- 独立服务可被任意浏览器/curl 访问，也可作为未来 `dsh-lan-scheduler` 的观测面；代价是需要自己处理 HTML/CSS/路由。
- 后续若要“嵌进 DSH 设置页”，再评估一个只读 client 壳调 `/status`；当前不预做。
