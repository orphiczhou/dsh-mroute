# dsh-lan-status · 立项报告（00）

> 状态：**v0.3.0 已实现：Host 值班台 + Client dock 入口；A 与本地 desktop 已真机验证，B/C/D 已部署 0.3.0（2026-11-23）**
> 日期：2026-11-20（v0.3.0 增补 2026-11-23）
> 定位：LAN 多节点 DSH 实验环境的**只读**状态面板，不参与调度、不写 DSH。

## 1. 问题

四台机器上的 DSH 是彼此独立的 `dsh web` 进程：

- 入口 URL 各带一次性 launch token，无法直接拼一个“总入口”；
- 每个节点有哪些活会话、哪些任务在跑，只能逐个节点看；
- 协调者 dsh-a 的任务台账在 `~/.dsh-lan-scheduler/state.json`，其他节点看不到；
- 用户需要一个页面回答“现在四台机器整体是什么状态”。

已有 `dsh-interconnect` 只传消息，`dsh-lan-scheduler` 只排队/派活，两者都不提供**跨节点只读视图**。

## 2. 目标 / 非目标

### 目标

1. 单页展示：节点属性（主机/OS/DSH 版本/角色/入口）、在线状态与延迟、CPU/内存/磁盘/负载、会话、运行中任务、最近终态任务。
2. 每节点可独立部署；agent 只暴露 `/self`，coordinator 聚合。
3. 只读：不写 DSH 状态、不写调度台账、不读消息正文、不持有 token。
4. Host 半保持独立 `node:http` 服务；Client 半只做 DSH 左侧 dock 入口与同源 `/lan-status/*` iframe，不把业务服务接进 `ctx.remote`/client assembly。
5. 可在 Windows（.24）与 Linux（.21/.23）混合环境运行。
6. v2 值班台：健康横幅、5 KPI、四列节点卡、详情抽屉、入口直链（网关自动登录）、任务全宽表、深浅主题。
7. v0.3.0：`sidebar.panellist` 图标 + `main` 面板，点击即在 DSH 界面内查看值班台。

### 非目标

- 不做鉴权/账号体系；假定可信 LAN。
- 不做历史存储/趋势图/告警。
- 不做任务控制（提交/取消）——那是 `sched_*` 的职责。
- 不做文件传输/DAG/多协调者。
- 不拼接 launch token，不代替用户打开各节点入口；v2 不做服务端 `/open` token 302。
- 不做趋势库/告警通知；v2 仅展示当前采样。

## 3. 架构

```
浏览器 ──GET /status──► dsh-a :3091（coordinator）
                         │  GET /self
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
     dsh-b :3092    dsh-c :3091    dsh-d :3091
```

- 每个节点：`node:http` + `lib/system.js`（node:os/CPU 两采样/磁盘）+ `ctx.agents.list()`。
- 协调者额外：读 `schedulerStateFile`（默认 `~/.dsh-lan-scheduler/state.json`）。
- 本地节点不递归：`instanceId` 等于 self 时直接复用 `self`，远端才 `agentUrl/self`。
- 聚合缓存 2s；单节点超时 2500ms；离线节点显示 `error`，不阻塞整页。
- **v0.3.0 Client 半**：`client.js` 向 `sidebar.panellist` 注册 `lan-status` 图标、向 `main` 注册同 key 面板；面板 iframe `/lan-status/`。Host 半通过 `ctx.inject(['webServer'])` 注册 `/lan-status/*` 同源代理到 `panelUrl`（默认协调者 3091），避免跨端口 CORS/CSP；`serve:false` 时只做代理，不起独立 HTTP 服务。

## 5. 安全

| 面 | 决定 |
|---|---|
| 认证 | 无；只监听可信 LAN，默认 `0.0.0.0:3091` |
| 凭据 | 不读 `DSH_INTERCONNECT_TOKEN`、provider key、launch token |
| 入口 | `entryUrl` 指向节点本地 `plugin-lan-trust` 网关（A 3095/B 3096/C/D 3095）；网关服务端换 cookie，token 不经过 3091、不存储 |
| 写面 | 无写路由；不注册工具；不改 DSH 状态 |
| 会话 | 只列 id/title/status/cwd，不读正文 |
| 任务 | 只读协调者台账；摘要可能含业务信息，台账按 600/ACL 保护 |
| 传输 | 明文 HTTP；按用户要求不使用 SSH 隧道，限可信网段 |
| 浏览器侧 | CSP `default-src 'self'`、`frame-ancestors 'self'`、`x-frame-options: SAMEORIGIN`（同源 iframe 需要）、`referrer-policy: no-referrer`、`nosniff`；移除 `ACAO:*` |
| Client 代理 | `/lan-status/*` 只挂在本节点 DSH web server 上，同源转发到 `panelUrl`；不开放 CORS，不代理任意 host（`panelUrl` 由配置固定） |
| 代发口 | 面板不提供 `/open/:id`/token 302；只把浏览器指向节点本地网关，由网关在服务端换 cookie |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| `ctx.agents.list()` 字段随宿主版本变化 | 全部读取包 try/catch；取不到会话/标题就降级，不让路由 500 |
| 端口 3091 冲突 | `/health` 必须实测；启动失败只 logger.error，部署检查不能只看 systemd active |
| 同机 A/B 台账混淆 | agent 不读台账；只有 coordinator 读自己的 `schedulerStateFile` |
| 面板被公网访问 | 文档明确只限 LAN；需要时加防火墙白名单/反代认证；v2 不加认证，不暴露公网 |
| 任务摘要泄漏 | 台账 600/ACL；面板不返回 prompt；摘要截断 |
| 入口 token 泄漏 | 面板只放 `entryUrl` base；网关在节点本地换 cookie，token 不进浏览器 URL/HTML；不读日志 token |
| 任意网页跨站读取 `/status` | 移除 `ACAO:*`，加 CSP/`frame-ancestors 'self'`；仅同源页面可读 |
| iframe 被 CSP/XFO 拒绝 | v0.3.0 改 `frame-ancestors 'self'` + `SAMEORIGIN`；不要退回 `none`/`DENY` |
| 单节点离线拖慢整页 | 单节点超时 2500ms；已知 D 离线时约 2.5s；后续可加 stale 缓存/熔断/1200ms 超时（专家建议，未实施） |

## 8. 决策

选择 **Host 独立 HTTP 服务 + Client 薄壳**：

- Host 半保持独立 `node:http` 值班台，可被任意浏览器/curl 访问，也作为未来观测面；不把业务服务接进 `ctx.remote`/client assembly。
- Client 半只注册 `sidebar.panellist` + `main`，用同源 `/lan-status/*` iframe 嵌入；避免跨端口 CORS/CSP，也不引入新业务 namespace。
- 代价：CSP 必须允许同源 iframe；代理只转发配置固定的 `panelUrl`，不做通用反代。
- 后续若要 native React 面板，再评估直接 fetch `/status` 或同源 API；当前不预做。
