## 0. 结论摘要（给赶时间的人）

**一句话：把“四张表”改成“一个值班台”——先回答整体是否健康，再让节点成为可扫、可点、可查的身份卡，最后才展开任务与会话明细。**

五个关键决定：

1. **总览 / 节点 / 工作台三层**：顶部健康横幅 + 5 个舰队指标 + 探针拓扑；中部四张节点卡；下部任务流与活会话。第一屏必须能回答“几个节点在线、谁离线、有没有任务在跑、有没有活会话”。
2. **节点卡负责“扫”，抽屉负责“查”**：卡片只放 7–9 个高价值字段；主机 uname、PID、完整 OS 串、原始 JSON 收进右侧抽屉，避免再次出现“主机列撑爆表格”。
3. **状态必须带来源与新鲜度**：每个数字标注“来自哪个接口 / 什么时候 / 是当前值还是本页观察值”。离线、陈旧、未采集、无数据是四种不同的视觉状态，不能都写成“暂无数据”。
4. **入口是受控动作，不是裸链接**：DSH Web 需要该节点 launch token。面板**不保存、不转发、不内置** token；采用“浏览器本机一次性 token → 节点 `/connect` 换 HttpOnly cookie”的原生表单方案，并保留“直接打开（若已解锁）/ 复制地址 / 申请 token”三条降级路径。详见 §7.5。
5. **不引入图表墙、不引入前端框架、不新增采集也能先上线 P0**：P0 只用现有 `/status` 数据 + 前端派生（在线/离线、延迟、本次会话最后成功、本页延迟采样、任务时长）。CPU/内存/磁盘、历史心跳、每节点台账、真实 interconnect 拓扑明确标注“需新增采集”。

**最大设计风险：token 的可用性与安全性是一对矛盾。** 做得越“一键”，越容易把 token 留在历史、密码管理器、截图或明文 LAN 里；做得越安全，值班人越可能打不开节点 UI。本文选择“浏览器本机提交、面板零持有”的中间路线，并把残余风险写在明面上，而不是假装无 token 可直达。

**P0 验收底线**：1440×900 第一屏无横向滚动；3/4 在线与 4/4 在线两种状态都能正确表达；dsh-d 离线卡不显示任何伪造的 CPU/内存/磁盘数字；点击节点卡能打开抽屉；入口对话框不向 `:3091` 发送 token；390px 宽手机可用。

## 1. 现状诊断

### 1.1 证据

- 截图（图 0-1）：页面由标题、4 个 chips、4 张同权重卡片和 3 张表组成；节点表 9 列，主机列被完整 `osRelease` 撑成多行；入口列是裸 `origin` 链接；任务表 ID 列过窄、结果列过长；整页没有节点身份、拓扑、层级和详情入口。
- 代码：`lib/status.js:301-461` 的 `renderHtml()` 是单文件内联 CSS/JS；CSS 仅 `:root` 8 个颜色变量 + 20 余行规则（`:309-337`）；`render()` 在 `:399-444` 依次拼三张表；`load()` 在 `:445-458` 固定 5 秒轮询，`document.hidden` 时跳过。
- 数据：`buildAggregateStatus()`（`lib/status.js`）返回 `ok/generatedAt/startedAt/coordinator/summary/nodes/sessions/tasks`；节点含 `instanceId/label/role/origin/agentUrl/hostname/platform/arch/osRelease/nodeVersion/dshVersion/pid/uptimeSec/startedAt/online/latencyMs/error/sessions/tasks`；任务 running 闭集 `queued|dispatching|running`，recent 只收 `succeeded|failed|cancelled` 且最多 12 条。
- 实测（2026-11-20T14:48Z）：`online=3/4`，dsh-d 为 `timeout`（2500ms），`sessions=0`，`runningTasks=0`，A 台账 `tasks.total=14`、recent 12 条；A/B/C 均 DSH `0.2.2-rc.3`、Node `v24.22.3`；页面 HTML 8783 bytes。
- 部署：A `.23:3091` coordinator、B `.23:3092`、C `.21:3091`、D `.24:3091`；四节点均为 `dsh web`，不是 desktop。面板无认证、LAN 明文、只读。

### 1.3 设计目标与非目标

**目标**

1. 值班人 3 秒内判断整体健康，10 秒内定位异常节点。
2. 节点卡在 1440px 下四列并排；每张卡回答“它是谁、活着吗、在干什么、怎么进去”。
3. 任务/会话从“表格单元格”变成可扫读、可展开、可筛选的行。
4. 入口可点击，但**不牺牲 token 安全**；所有安全边界在 UI 上可见。
5. 纯前端重构即可上线 P0；不破坏 `/status` 契约、不引入 client 半、不引入构建步骤。
6. 深浅色、移动端、键盘、空/错/离线/陈旧态完整。

**非目标（本期不做）**

- 不做鉴权/账号体系；不把面板暴露到公网。
- 不做任务提交/取消/重试（那是 `sched_*` 的职责）。
- 不做会话正文、消息、prompt 展示。
- 不做历史数据库、告警、通知、多协调者。
- 不拼接、不保存、不代理 launch token。
- 不为了“看起来丰富”伪造 CPU/内存/磁盘/趋势数据。

### 1.4 成功标准

| 指标 | 目标 | 测法 |
|---|---|---|
| 首屏判断 | 5 位同事中至少 4 位在 5 秒内答对“几个在线/谁离线/有无运行任务” | 验收时现场提问，不引导 |
| 首屏完整性 | 1440×900 内看到 header、健康横幅、舰队指标、拓扑、至少第一排节点卡 | 截图 + `document.scrollingElement.scrollWidth === clientWidth` |
| 节点定位 | 从看到异常到打开对应节点抽屉 ≤ 2 次点击 | 手工计时 |
| 入口安全 | 面板 HTML/JS/localStorage/sessionStorage 中无 token；提交表单的目标是节点 origin，不是 `:3091` | DevTools Network + 静态 grep |
| 数据诚实 | 离线/陈旧/未采集/空 四种状态视觉可区分 | 状态矩阵走查 |

### 2.2 综合结论

1. **总览—详情双层是同类产品的共识**（Beszel、Portainer、Netdata、K8s Dashboard）：总览只放“判断健康”的信息，详情才放身份、资源、事件。当前面板把两者压在一张表里，是信息密度失衡的根因。
2. **状态页的重点不是图，是“现在能不能放心”**（Grafana 最佳实践、Uptime Kuma）：先给全局结论，再给证据；不要用图表填满空白。
3. **拓扑只有在“边有含义”时才值得画**（Grafana Node Graph）：本项目现有数据只能证明“协调者探测到节点 /self”，不能证明 dsh-interconnect 对等互通。因此拓扑必须标注“探针链路”，真实 mesh 留 P1。
4. **入口在同类产品里都是“受控动作”**（K8s Dashboard 的 Bearer Token、Portainer 的登录）：没有 token 就不该伪装成普通链接。本项目要把 token 流程做成显式对话框，而不是把 token 塞进页面。
5. **视觉高级感来自体系，不来自装饰**：栅格、间距、字号、状态色、空态、动效一致，才会像产品而不是原型。

## 3. 信息架构

### 3.1 三层结构

```text
L0 全局态势（3 秒）
├─ 全局 Header：品牌 / 环境 / 总体健康 / 刷新 / 主题
├─ 健康横幅（仅异常时出现）：谁坏了、坏了多久、下一步
├─ 舰队指标：节点在线、活会话、运行任务、最近失败、平均延迟
└─ 探针拓扑：A→B/C/D 的延迟与可达性（明确“非对等互通”）

L1 节点（10 秒）
├─ 节点卡 ×4：身份 / 状态 / 3 个计数 / 3 个资源占位 / 版本 / 入口
└─ 节点抽屉（点卡片/拓扑/深链）
   ├─ 概览：身份、版本、进程、探针、资源、入口
   ├─ 会话：该节点的活会话
   ├─ 任务：该节点相关任务
   └─ 原始数据：该节点的 JSON（只读、可复制）

L2 工作负载（30 秒）
├─ 任务流：运行中 / 最近 12 条；筛选、搜索、展开摘要
└─ 活会话：当前活 agent；空态解释“重启后为空是真实结果”

L3 证据与说明
├─ 数据来源、生成时间、只读声明
├─ 原始 JSON / 复制诊断
└─ token 安全说明与申请路径
```

### 3.2 页面区域规格

| 区域 | 回答的问题 | 主要组件 | 数据 | 是否首屏 |
|---|---|---|---|---|
| Header | 这是什么、整体好坏、数据新不新 | 品牌、环境徽标、健康 pill、刷新间隔、刷新按钮、主题 | `summary/generatedAt/coordinator` | 是 |
| Health Banner | 哪里坏了、影响多大、怎么办 | 图标、标题、详情、动作 | `nodes[].online/error`、本地陈旧判断 | 是（仅异常） |
| Fleet Stats | 一眼看几个数 | 5 个 stat | `summary`、`latencyMs`、`tasks.recent` | 是 |
| Probe Topology | 哪条探针不通、延迟多少 | 4 个节点 chip + 3 条边 | `nodes[].online/latencyMs/error` | 是 |
| Node Grid | 每个节点是谁、在干什么 | 4 张节点卡 | `nodes[]` + 派生 | 是（至少第一排） |
| Workbench | 有什么任务/会话、是否失败 | 任务 tabs、筛选、任务行、会话列表 | `tasks`、`sessions` | 第二屏 |
| Footer | 数据从哪来、能信到什么程度 | 来源、版本、安全说明 | 静态 + `generatedAt` | 否 |
| Node Drawer | 单节点全貌与证据 | 4 个 tab | 单节点 + tasks/sessions | 覆盖层 |
| Entry Dialog | 怎么进入该节点 UI | 直接打开/贴 token/复制/帮助 | `node.origin` | 覆盖层 |

### 3.3 内容优先级（从高到低）

1. 整体是否健康（在线数、离线节点、最近失败）。
2. 哪个节点异常、异常原因、最后成功时间。
3. 当前有没有活会话/运行任务（值班交接的关键）。
4. 节点身份：label、role、host、端口；A/B 同机必须能区分。
5. 版本：DSH、Node；用于判断“是不是版本漂移”。
6. 入口与 token 状态。
7. 资源占用（P1；P0 只显示“未采集”，不显示假数）。
8. 历史趋势（P1/P2）。
9. PID、完整 uname、原始 JSON（抽屉/证据层）。

### 3.4 数据字典与采集状态

> 图例：**现有** = `/status` 已返回；**派生** = 前端用现有数据计算；**新增** = 需要改采集/契约；**不可得** = 浏览器同源策略或 DSH 未暴露。

| 字段 | 来源 | 状态 | P0 展示位置 | 说明 |
|---|---|---|---|---|
| `instanceId/label/role` | `/self.node` | 现有 | 卡片标题、角色徽标、抽屉 | 角色是身份，不是健康 |
| `online/latencyMs/error` | 聚合器 | 现有 | 卡片状态行、拓扑边、横幅 | `error` 目前是 `timeout` 等 |
| `hostname/platform/arch` | `node:os` | 现有 | 卡片副标题、抽屉 | 卡片只显示 hostname + OS 短名 + 端口 |
| 机位（host/IP/port） | `hostname/origin` | 现有 | 卡片第二行、抽屉 | 只表示主机与入口端口；物理机架/位置未采集（P1 可加 `location`） |
| `osRelease` | `node:os` | 现有 | 抽屉；卡片解析为“Ubuntu · x64” | 完整 uname 只进抽屉，默认折叠 |
| `dshVersion/nodeVersion` | 配置 / `process.version` | 现有 | 卡片底部、抽屉 | 版本缺失显示“版本未知” |
| `pid/uptimeSec/startedAt` | `process` / 配置 | 现有 | 抽屉 | 卡片最多显示 uptime |
| `origin/agentUrl` | 配置 | 现有 | 入口对话框、抽屉 | `origin` 不含 token |
| `sessions[]` | `ctx.agents.list()` | 现有 | 卡片计数、工作台、抽屉 | 仅活 agent；重启后为空是真实结果 |
| `tasks.running/recent` | 协调者台账 | 现有 | 卡片计数、工作台、抽屉 | 仅 A 台账；recent 最多 12 条 |
| `tasks[].createdAt/finishedAt` | 台账 | 现有 | 任务行“耗时” | `finishedAt - createdAt` |
| `summary/generatedAt/coordinator` | 聚合器 | 现有 | Header、Footer、陈旧判断 | 服务器聚合时间 |
| 节点状态 `ok/degraded/offline/stale/unknown` | 派生 | 派生 | 卡片、拓扑、横幅 | 规则见 §7.1 |
| 最后成功（本页） | 前端轮询 | 派生 | 离线卡、Header | 仅本次页面会话；刷新页面丢失 |

| 任务耗时/相对时间 | `createdAt/finishedAt` | 派生 | 任务行 | 运行中显示“已运行” |
| CPU 使用率/负载 | `node:os` | 新增 | 卡片资源区、抽屉 | P1；Windows `loadavg` 恒 0，需注明 |
| 内存 used/total | `node:os` | 新增 | 卡片资源区、抽屉 | P1；`totalmem/freemem` |
| 磁盘 used/total | `fs.statfs` | 新增 | 卡片资源区、抽屉 | P1；需配置监控路径；跨平台注意 |
| 网络/温度 | 平台命令/传感器 | 新增 | 抽屉 | P1/P2；跨平台成本高 |
| 心跳历史 | 服务端环形缓冲 | 新增 | 卡片 sparkline、抽屉 | P1；否则只有本页观察 |
| 每节点调度台账 | 各节点 `schedulerStateFile` | 新增 | 任务来源徽标、抽屉 | P1；同机 A/B 必须不同路径，避免污染 |

| 会话正文/消息数 | 未暴露 | 不可得 | 不展示 | 隐私非目标 |

## 4. 用户旅程

### 4.1 交接班：30 秒判断“能不能走”

**场景**：08:55，值班人打开面板，准备把班交给下一位。

1. Header 健康 pill：`降级 · 3/4 在线`（琥珀），旁边 `2s 前更新`。
2. 健康横幅：`dsh-d 离线 · timeout（2500ms）· 本次会话最后成功 08:46:12`，动作 `[重试] [查看 dsh-d]`。
3. 舰队指标：`节点 3/4`、`活会话 0`、`运行任务 0`、`最近失败 1`、`平均延迟 1.7ms`。
4. 拓扑：A→B 2ms 实线绿，A→C 3ms 实线绿，A→D 虚线红 `timeout`。
5. 节点卡：dsh-a/b/c 绿色左侧健康条；dsh-d 降饱和、红色健康条、`最后在线 —（本次会话未见）`。
6. 任务流：`最近任务 12`，失败 1 条，标题 `probe-d2`，节点 dsh-d。
7. 交接结论：`dsh-d 面板探针不通，A 台账最近一条失败也在 dsh-d；其余三节点正常；无运行任务。`

**设计要点**：不需要点开任何节点就能完成交接；离线原因和最后时间在横幅和卡片上直接可见；不伪造 dsh-d 的 CPU/内存。

### 4.2 单节点异常：2 分钟定位

1. 横幅点击 `[查看 dsh-d]` → 抽屉打开，URL 变为 `?node=dsh-d`。
2. 概览 tab：`在线 false`、`error timeout`、`latencyMs 2500`、`origin http://192.168.3.24:3081`、`agentUrl http://192.168.3.24:3091`、`DSH 版本未知（离线）`。
3. 任务 tab：该节点相关任务，失败 `probe-d2` 的 summary；复制任务 ID。
4. 原始数据 tab：该节点的 JSON（离线时只有 `instanceId/label/role/origin/agentUrl/online/latencyMs/error`）。
5. 点击 `[打开 UI]`：如果浏览器已解锁，直接新标签；否则弹 token 对话框；仍失败则 `[复制诊断]`，把节点、时间、error、origin 发给节点 owner。
6. 不在面板里做重启/取消任务——只读边界在抽屉底部明示。

**设计要点**：抽屉是“证据页”，不是“操作页”；所有动作只有复制/打开/重试，没有写操作。

### 4.3 进入节点 UI：两条路径，绝不假装直达

**路径 A：本浏览器已解锁（有 `dsh-auth` cookie）**

1. 节点卡 `[打开 UI]` → 对话框默认选中“直接打开（若已解锁）”。
2. 点击 `[在新标签打开]` → `node.origin` 新标签；若节点接受 cookie，直接进入；若要求 token，回到路径 B。

**路径 B：使用 launch token 解锁**

1. 对话框选中“使用 launch token”。
2. 从节点 owner 处获得 token（只取 `token=` 后的部分），粘贴到密码框。
3. 点击 `[解锁并打开]` → 原生 GET 表单直接提交到 `node.origin/connect?interactions=answer`，token **不经过 3091 面板服务**。
4. 节点校验成功 → `302` + `Set-Cookie: dsh-auth` → 新标签进入 DSH Web。
5. 面板侧清空输入框；显示 toast：`已在新标签打开；若仍要求 token，说明 token 无效或已过期。`

**路径 C：复制/申请**

- `[复制入口地址]`：复制 `http://192.168.3.24:3081`（不含 token）。
- `[如何获取 token]`：展开说明，告诉用户向节点 owner 索取一次性 launch URL，不要把整条 URL 发群。
- 如果 `origin` 未配置：按钮禁用，文案“该节点未配置入口”。

**设计要点**：对话框第一行就写“DSH Web 需要该节点自己的 launch token；面板不保存、不转发”。用户不会以为这是普通链接。

### 4.4 任务复盘

1. 工作台 `最近任务`，筛选 `失败`。
2. 任务行显示：状态图标、标题、ID、节点、worker、尝试次数、耗时、完成相对时间。
3. 点击行展开：`结果/错误` 全文（可折叠）、任务 ID、开始/完成、`attempts/maxAttempts`。
4. `[复制任务 ID]`，贴到调度会话或台账排查。
5. 任务数据来源徽标：`来源 dsh-a 台账 · 最近 12 条终态`，避免误以为全量历史。

**设计要点**：长 summary 不再挤在表格单元格，而是展开后的全宽文本块；失败与取消分色分图标。

### 4.5 手机巡检

1. 手机打开同一 URL；Header 压缩为品牌 + 健康 pill + 菜单。
2. 健康横幅、2×2 舰队指标；拓扑变成竖排“A→B/C/D”列表，不画 SVG。
3. 节点卡单列；每张卡只保留身份、状态、3 个计数、入口/详情。
4. 点卡片 → 全屏抽屉，底部 tab 切换；`Esc`/下滑关闭。
5. 入口对话框全屏；token 输入框适配手机键盘；提示“建议在桌面浏览器完成 token 解锁”。

**设计要点**：手机优先完成“看”和“判断”，不强行在手机上完成复杂的 token 粘贴。

### 5.3 探针拓扑

**规格**

**任务行规格**

| 列 | 宽度 | 内容 | 响应式 |
|---|---|---|---|
| 状态 | 20px | 图标 + 可访问文本 | 始终 |
| 标题 | `minmax(0,1fr)` | 标题 1 行省略；下一行 mono ID 11px | 始终 |
| 节点/worker | 140px | `dsh-a / w-2`；节点用角色点 | <1024 隐藏 worker，只留节点 |
| 尝试 | 56px | `1/3`；`maxAttempts` 缺失显示 `1` | <900 收进展开区 |
| 耗时 | 64px | `4.4s`/`48s`/`2m`；运行中显示已运行 | 始终 |
| 完成 | 88px | 相对时间 `2 分钟前`，title 绝对时间 | <640 移到第二行 |
| 展开 | 24px | `›`/`⌄` | 始终 |

- 展开区：`结果`（summary）或 `错误`（lastError）优先；两者都有时先错误后结果；保留换行，最多 6 行，超出“展开全文”。
- 筛选：状态 chips（全部/成功/失败/取消/运行中，带计数）、节点下拉、搜索（标题/ID/worker）；筛选状态写入 URL。
- 排序：默认 `finishedAt` 降序；运行中按 `createdAt` 升序；P0 不做多列排序。
- 空态：
  - 运行中：`队列为空` + `协调者当前没有排队/分派/运行中的任务`。
  - 最近：`台账暂无终态任务` + `任务完成后会出现在这里（最多 12 条）`。
  - 筛选后：`没有匹配的任务` + `[清除筛选]`。

**会话列表规格**

- 每行 64px：状态点、标题（fallback“未命名会话”）、节点徽标、cwd 截断（中间省略）、sessionId mono + 复制按钮。
- 点击行：展开详情（sessionId/cwd/status/节点），不做“打开会话”（DSH 没有稳定深链）。
- 空态必须解释：`当前没有活会话` / `ctx.agents.list() 只列活 agent；节点重启后为空是真实结果，不是采集失败。`
- 超过 5 条时列表内滚动（max-height 360px），不撑高页面。

## 6. 视觉规范

### 6.1 设计语言：夜间值班台，不是“更花的表格”

**隐喻**：一块挂在值班室墙上的状态板——深色底、细线分区、低饱和表面、少量高信号颜色；信息像仪表一样对齐，不像营销页一样堆装饰。

四条纪律：

1. **表面平、层级薄**：卡片只有 1px 边框 + 一级背景差；不用大面积渐变、玻璃拟态、发光边框。
2. **一个强调色**：青蓝色只用于链接、选中、焦点、主按钮；绿色/琥珀/红色只表示状态，不拿来做装饰。
3. **数字对齐**：所有计数、延迟、版本用 tabular numerals；单位小一号；右对齐或小数点对齐。
4. **留白是分组手段**：先用间距分组，再用边框；不要给每个区块都套卡片。

允许的装饰只有两处：页面顶部一层极淡的径向光晕（`radial-gradient`，透明度 ≤6%），以及拓扑区域一层 24px 点阵网格（透明度 ≤4%）。其余全部靠排版和色彩体系。

### 6.2 栅格、间距、圆角、阴影

**页面栅格**

- 12 列，`max-width: 1440px`，水平居中；桌面左右 padding 32px，列间距 24px。
- 内容区最小宽度 0；所有 grid/flex 子项加 `min-width:0`，防止长 URL/uname 撑破。
- 节点区在 12 列内使用 4/2/1 列（见 §5.8），不强行嵌套 subgrid。
- 阅读型文本（说明、错误详情）最大 72ch；任务摘要最大 80ch。

**间距 token**

| Token | 值 | 典型用途 |
|---|---|---|
| `--space-1` | 4px | 图标与文字、徽标内边距 |
| `--space-2` | 8px | 标签与值、按钮组 |
| `--space-3` | 12px | 卡片内行距、表格单元格 |
| `--space-4` | 16px | 卡片内区块、移动端页边 |
| `--space-5` | 20px | 卡片 padding（紧凑） |
| `--space-6` | 24px | 卡片 padding（标准）、栅格 gutter |
| `--space-8` | 32px | 区块间距、桌面页边 |
| `--space-10` | 40px | 大区块分隔 |
| `--space-12` | 48px | 页面顶部/底部留白 |
| `--space-16` | 64px | 空态/错误页留白 |

**圆角**

- `--radius-sm: 6px`：徽标、输入框内小元素。
- `--radius-md: 8px`：按钮、输入框、tab。
- `--radius-lg: 12px`：卡片、对话框。
- `--radius-xl: 16px`：抽屉/移动端 sheet。
- `--radius-full: 999px`：状态 pill、chips。
- 不要混用 10/14/18 这类无体系的圆角。

**边框与阴影**

- 边框统一 1px；hover 只改变边框色/背景，不加粗。
- 深色卡片阴影：`0 1px 0 rgba(255,255,255,.03) inset, 0 8px 28px rgba(0,0,0,.28)`。
- 浅色卡片阴影：`0 1px 2px rgba(15,23,42,.05), 0 8px 24px rgba(15,23,42,.06)`。
- 弹层阴影：深色 `0 16px 48px rgba(0,0,0,.45)`；浅色 `0 16px 48px rgba(15,23,42,.18)`。
- 不使用“外发光”表示选中；选中用 2px accent ring 或左侧 3px 竖条。

**字体栈**（不加载外部字体，LAN 离线可用）

**对比度纪律**

- 正文/次要正文目标 ≥4.5:1；大字号（≥20px semibold）和 UI 边框目标 ≥3:1。
- 深色：`--text-primary` 在 `--bg-elev-1` 上约 15:1；`--text-secondary` 约 7:1；`--text-tertiary` 约 4.8:1。浅色同量级。
- 状态色不直接当正文色大面积使用；用 `*-fg` 在小字号上，或 `*-bg` 做底。
- 不用纯红/纯绿；`#ff0000`/`#00ff00` 在深色上刺眼且对比不稳定。
- 任何“仅靠颜色”的表达都算不合规：状态点必须配文字，任务行必须配图标/状态词。

**主题切换**

- 默认跟随 `prefers-color-scheme`；用户手动切换后写入 `localStorage["lan-status-theme"]`（只存 `dark|light`，不存任何 token）。
- `<head>` 内联 3 行脚本先设置 `data-theme`，避免首屏闪白。
- 切换按钮：太阳/月亮 16px 图标 + `aria-label="切换到浅色/深色模式"`，不做动画炫技。
- 打印：强制浅色；隐藏刷新/主题按钮/抽屉遮罩。

### 6.5 状态语义与全局健康

**节点状态**

| 状态 | 图标 | 颜色 | 文案模板 | 卡片处理 |
|---|---|---|---|---|
| `online` | ● 实心 | 绿 | `在线 · 探针 2ms · 2s 前` | 正常；健康条绿 |
| `stale` | ◐ 半实心 | 琥珀 | `在线 · 数据陈旧 32s` | 正常但降饱和 10%；提示重试 |
| `offline` | ○ 空心 | 红 | `离线 · timeout（2500ms）` | 降饱和 40%；健康条红；不伪造资源 |
| `unknown` | ◌ 虚线 | 灰 | `等待首次数据` | 骨架；不显示 0 |
| `maintenance`（P1） | ◍ | 灰蓝 | `维护中 · 暂停告警` | 不进入全局横幅；卡片加“维护”徽标 |

**任务状态**

| 状态 | 图标 | 颜色 | 文案 |
|---|---|---|---|
| `queued` | ◷ | 中性 | 排队 |
| `dispatching` | ⇢ | 信息 | 分派中 |
| `running` | ▶（脉冲） | 信息 | 运行中 |
| `succeeded` | ✓ | 绿 | 成功 |
| `failed` | ✕ | 红 | 失败 |
| `cancelled` | ⊘ | 中性 | 取消 |

**全局健康**

| 级别 | 条件 | Header pill | 横幅 |
|---|---|---|---|
| `ok` | 所有节点在线且新鲜；近 15 分钟无失败 | `正常 · 4/4 在线` 绿 | 不显示 |
| `degraded` | 1 个节点离线/陈旧，或近 15 分钟有 1 条失败 | `降级 · 3/4 在线` 琥珀 | 琥珀横幅，列明节点/原因 |
| `critical` | ≥2 节点离线，或协调者数据陈旧，或 `/status` 连续失败 | `异常 · 2/4 在线` 红 | 红色横幅，列明影响 |
| `unknown` | 首次加载/无数据 | `连接中…` 灰 | 不显示，显示骨架 |

规则：

- 单节点离线用**琥珀横幅**而不是红色，避免“一个 agent 掉了”就全屏告警；节点卡本身仍用红色表示离线。
- 近期失败按 `finishedAt` 判断；没有历史时用 `recent` 12 条中的失败数，标注“近 12 条”。
- 横幅**不可手动关闭**（避免掩盖故障）；P1 可加“维护中”配置，但必须显示灰色维护徽标。
- `aria-live="polite"` 只播报全局健康级别变化与错误，不播报每 10 秒的普通刷新。

### 6.7 图表与数据可视化策略

**原则：没有数据就不画图。**

- **P0 只做三种可视化**：
  1. 节点卡顶部 3px 健康条（状态，不是图表）。
  2. 本页延迟 sparkline（前端采样，明确“本页观察”）。
  3. 资源 meter 占位（未知态，不是 0%）。
- **P1 才做**：服务端心跳历史（60–120 个采样）、CPU/内存/磁盘 meter、任务耗时分布/成功率。仍需标注窗口与样本量。
- **不做**：饼图、环形进度、仪表盘指针、3D、面积堆叠、双 Y 轴、平滑插值。4 个节点用不上。
- **不伪造**：未知显示 `—` 或虚线 track；离线不显示 0；历史不足不画趋势线，显示“采样中（还需 N 个点）”。
- **图表配色**：只使用语义色；同一图不超过 3 种颜色；线宽 1.5px；网格线仅水平、1px、`--border-subtle`；坐标轴标签 11px tertiary。
- **可读性**：图必须有标题、时间窗口、来源；hover 显示精确值；键盘 focus 可读出最后值。

## 7. 交互规格

### 7.1 刷新、新鲜度与失败退避

**默认参数**

| 参数 | 值 | 说明 |
|---|---|---|
| 自动刷新 | 10s（可选 5s/10s/30s/暂停） | 默认从 5s 提到 10s，降低无意义闪烁；写入 `localStorage["lan-status-refresh"]` |
| 手动刷新 | 立即，带 `?refresh=1` | 绕过服务端 2s 聚合缓存 |
| 请求超时 | 8s（前端 `AbortController`） | 服务端单节点 2500ms，聚合最多约 2.5s |
| 陈旧阈值 | `max(3 × 刷新间隔, 30s)` | 超过则 Header 标“数据陈旧”，卡片琥珀 |
| 退避 | 10s → 20s → 40s → 60s 上限 | 成功后重置；手动刷新不等待退避 |
| 页面隐藏 | 暂停轮询 | `visibilitychange` 可见时，如已过期立即刷新 |
| 并发 | 单飞 | 上一次未结束不发下一次；`AbortController` 取消过期请求 |

**状态机**

```text
idle ──load──► loading ──ok──► success ──timer──► loading
                  │                 │
                  └──error──► error ─┘
                               │
                               └──backoff──► loading（保留旧数据）
```

**规则**

- 首次加载：显示 skeleton；不显示“暂无数据”。
- 刷新成功：更新 `lastSuccessAt`、`generatedAt`、数据；Header 显示 `2s 前更新`，每秒更新相对时间。
- 刷新失败：**保留上一次成功数据**；顶部出现琥珀/红条 `无法刷新 · 显示 22:48:24 的数据 · 18s 后重试`；Header 的健康 pill 变“数据陈旧”，不把旧数据继续标绿。
- 连续失败 3 次：横幅升级为红色，动作 `[立即重试] [查看端点]`。
- 手动刷新：按钮进入 loading（旋转 600ms 最短），禁用防连点；成功后 toast `已更新`（可选，不打扰）。
- 自动刷新不改变滚动位置、不关闭抽屉、不重置筛选、不折叠已展开任务。
- 更新 DOM 用 keyed patch（`data-node-id`/`data-task-id`），不要整段 `innerHTML` 重建；避免闪烁和焦点丢失。
- 时间显示：<60s 用“刚刚/N 秒前”；<60m 用“N 分钟前”；<24h 用“N 小时前”；否则绝对时间。`title` 永远给绝对时间。

### 7.2 节点详情抽屉

**打开**

- 节点卡整卡点击（按钮/链接除外）、拓扑 chip、任务行的节点徽标、深链 `?node=dsh-a`。
- 打开时 `history.pushState({node:"dsh-a"}, "", "?node=dsh-a")`；不整页刷新。
- 抽屉出现后焦点到标题；背景 `inert`（或 `aria-hidden` + tabindex 管理）；焦点陷阱。

**关闭**

- 右上 ×、`Esc`、点击遮罩、浏览器后退。
- 关闭后焦点回到触发元素；`history.back()` 若当前是 push 进来的；直接深链打开时用 `replaceState` 清参数。

**Tab**

| Tab | 内容 | 空态 |
|---|---|---|
| 概览 | 身份、版本、进程、资源、探针、入口 | 离线时只显示已知字段 + 错误；资源“未采集” |
| 会话 | 该节点的活会话 | `该节点当前没有活会话` + 解释 |
| 任务 | 该节点相关任务（running + recent） | `该节点暂无任务记录`；agent 加“仅协调者读台账”说明 |
| 原始数据 | 该节点 JSON，`<pre>`，可复制 | 离线时显示现有最小对象 |

**数据更新**：抽屉打开期间轮询继续；只更新字段，不重建 tab；如果节点消失，显示 `节点已不在配置中`，保留最后数据，提供关闭。

**deep link**：`?node=dsh-a&tab=tasks`；未知节点显示轻量错误页/抽屉空态，不跳转。筛选参数与节点参数可共存，互不覆盖。

### 7.3 筛选、搜索、排序

- **任务筛选**：状态（全部/运行中/成功/失败/取消，带计数）、节点（全部 + 4 节点）、搜索（标题/ID/worker，`includes`，大小写不敏感）。
- **会话筛选**：节点（全部 + 4 节点）、搜索（标题/sessionId/cwd）。
- **URL 状态**：`?status=failed&node=dsh-d&q=probe`；使用 `replaceState` 更新，避免每敲一个字都产生历史记录；刷新/分享可还原。
- **清除**：有任一筛选时显示 `[清除筛选]`；清除后回到默认（最近任务、全部状态、全部节点）。
- **计数**：chip 上的计数是“当前搜索结果内”的计数还是全量？统一为**全量**，避免筛选后数字跳变；空结果时显示“0 条匹配”。
- **排序**：默认 `finishedAt` 降序；运行中置顶（`running` 组先于 recent）；P0 不做列排序；P1 可加“按节点/状态”。
- **搜索防抖**：150ms；不做正则/模糊高亮，避免 XSS 与性能问题；空查询显示全部。
- **无结果**：`没有匹配的任务` + `[清除筛选]`；不要显示成“暂无任务”。

### 7.4 拓扑交互

- 节点 chip hover：边框 accent、显示 tooltip（完整 label/host/origin）；点击打开抽屉。
- 边 hover：显示 `A→B · 2ms · 成功于 22:48:24`；离线边显示 `timeout 2500ms`。
- 键盘：chip 是 `<button>`；Tab 顺序 A→B→C→D；Enter 打开；`aria-label="dsh-b，在线，2 毫秒"`。
- 移动端：不渲染 SVG，渲染 `<ul>`；每行 `A → dsh-b · 2ms · 在线`，点击开抽屉。
- 图例可折叠；首次显示一行说明“仅面板探针，非 dsh-interconnect 对等拓扑”。
- 节点数 >8 时（未来）退化为列表 + 分组；不做力导向布局。

### 7.5 进入节点 UI：安全设计（核心）

#### 7.5.1 约束

- 每个节点的 DSH Web 都需要该节点自己的 launch token；`origin` 只是 base URL，不含 token。
- 面板无认证、LAN 明文；任何能打开面板的人都能看到页面与 `/status`。
- token 不能写进仓库、HTML、JS 常量、面板配置、日志、localStorage/sessionStorage。
- DSH `/connect` 接受 `GET /connect?token=<launch-token>&interactions=answer`，成功返回 `302` 并设置 `dsh-auth` HttpOnly cookie。
- 浏览器同源策略：面板无法读取节点 cookie，无法判断“是否已解锁”，也无法读取 `/connect` 的响应。
- 同机 A/B 的 cookie 不按端口隔离；不要假设解锁 A 就等于解锁 B。

#### 7.5.2 方案比较

| 方案 | 做法 | 安全 | 可用性 | 结论 |
|---|---|---|---|---|
| A. 面板服务端保存 token，`/open?node=` 302 | 配置/环境变量存 token，服务端拼 URL | **差**：所有看面板的人获得入口权限；token 进配置/日志；违背立项非目标 | 好 | **拒绝** |
| B. 前端常量/HTML 内嵌 token | 生成页面时写入 | **差**：仓库/源码/截图泄漏；所有人可用 | 好 | **拒绝** |
| C. iframe 嵌入节点 UI | 面板内嵌 `origin` | 差：X-Frame-Options/CSP 多半拒绝；token 仍需要；cookie 第三方上下文问题 | 差 | **拒绝** |
| D. 浏览器本机表单提交 token 到节点 `/connect` | 面板只提供表单，token 从输入框直接提交给节点 | **中**：token 不经面板服务器、不存储；但会进新标签 URL/历史，LAN 明文可嗅探 | 中 | **P0 采纳** |
| E. 本机 helper / 自定义协议 | `dsh-open://node/dsh-c`，helper 从系统钥匙串取 token 并打开 | **较好**：token 不进浏览器历史；但需安装/维护 helper，跨平台成本高 | 好 | **P2 评估** |
| F. 复制完整 launch URL 到剪贴板 | 节点 owner 发一次性 URL，用户自己打开 | 中：token 在剪贴板/聊天记录；无面板参与 | 差 | **降级路径** |

#### 7.5.3 采纳流程：浏览器本机 token → cookie

```text
值班人                面板页 (:3091)                 浏览器                   节点 dsh-c (:3081)
  │ 点击 [打开 UI]          │                            │                          │
  │───────────────────────>│                            │                          │
  │ 对话框：直接打开/贴 token│                            │                          │
  │ 粘贴 token（仅输入框）   │                            │                          │
  │ 点击 [解锁并打开]        │                            │                          │
  │───────────────────────>│ 原生 <form method=get>      │                          │
  │                        │ action=node.origin/connect  │                          │
  │                        │ target=_blank               │                          │
  │                        │───────────────────────────>│ GET /connect?token=…     │
  │                        │                            │─────────────────────────>│
  │                        │                            │                          │ 校验 token
  │                        │                            │                          │ Set-Cookie: dsh-auth
  │                        │                            │<─────────────────────────│ 302 /
  │                        │                            │ GET / (带 cookie)        │
  │                        │                            │─────────────────────────>│
  │                        │                            │<─────────────────────────│ DSH Web UI
  │ 面板清空输入框           │                            │                          │
  │ 新标签已打开             │                            │                          │
```

**关键点：表单提交是浏览器 → 节点的顶层导航，不经过 3091 的 JS/fetch。** 面板只提供 `action` 和输入框；token 不会出现在面板的网络请求、日志、localStorage 中。

#### 7.5.4 表单规格

```html

<form id="entry-form"
      method="get"
      action="http://192.168.3.21:3081/connect"
      target="_blank"
      autocomplete="off">

  <label for="launch-token">Launch token</label>
  <input id="launch-token"
```

**实现约束**

- `action` 只能取 `node.origin`（`http://`/`https://` 白名单校验），不能取用户输入；`origin` 缺失时禁用 token 流程。
- 不用 `fetch`/`XMLHttpRequest` 提交 token；不用 `window.open` 拼接带 token 的 URL；不用 `location.href` 在当前页跳转。
- 不在 URL、`data-*`、日志、analytics、错误上报中写 token；输入框值只在提交瞬间存在。
- 不提供“显示 token”开关；不提供“记住 token”；不在 `localStorage`/`sessionStorage`/cookie 中保存。
- 表单提交后 `setTimeout` 清空；关闭对话框、切换 tab、页面卸载时也清空。
- 设置 `<meta name="referrer" content="no-referrer">`，避免面板把自身 URL/查询参数带给外部；节点侧的 Referrer-Policy 由节点负责。
- 新标签使用 `target="_blank"`；现代浏览器隐含 `noopener`，不要用 `window.opener` 回传任何数据。

#### 7.5.5 安全边界与残余风险

| 风险 | 说明 | 缓解 | 剩余风险 |
|---|---|---|---|
| token 进入浏览器历史 | `/connect?token=…` 会留在新标签的 URL/历史 | 一次性 token；建议无痕窗口；完成后关闭标签；P2 节点支持 POST/短期 token | 中 |
| token 被同网段嗅探 | 全链路 HTTP 明文 | 只限可信 LAN；P2 用 HTTPS 反代；不要在公共 Wi-Fi 使用 | 高（现有架构） |
| 共享浏览器残留 | 密码管理器/表单历史可能保存 | 不存储；`autocomplete=new-password`；关闭清除；建议无痕 | 中 |
| 面板被冒充 | 无认证，任何人可仿页面 | 核对 URL/IP；P2 反代认证；文档明确“只从已知地址打开” | 中 |
| XSS 窃取 token | 页面内联 JS + 用户数据 | 全部 `textContent`；不引入第三方脚本；CSP；URL 属性白名单 | 低 |
| CORS 泄露任务摘要 | `/status` 当前 `Access-Control-Allow-Origin:*` | P1 移除或限制到面板 origin；面板同源不需要 CORS | 中（现有） |
| 同机 cookie 串扰 | cookie 不区分端口，A/B 共享 host | 不假设一次解锁通用；P2 分域名/反代路径 | 中 |
| Referer 泄露 | 含 token 的 URL 跳外链可能带 Referer | 面板 `no-referrer`；节点侧设置 `Referrer-Policy`；不要把含 token URL 发外部 | 中 |
| 日志留存 | 节点/反代可能记录 query | 节点 owner 清理/脱敏；P2 改 POST | 中 |
| 截图/肩窥 | 输入框可见/屏幕共享 | 密码框、无显示开关、不记忆；提示注意环境 | 低 |

**明确不做**：不把 token 放进面板配置；不做服务端 `/open` 重定向；不做“无 token 直达”的假按钮；不把 `dsh-auth` cookie 转发到面板。

#### 7.5.6 文案

- 对话框标题：`打开 dsh-c 的 DSH Web`
- 说明：`DSH Web 需要该节点自己的 launch token。面板不保存、不转发 token；token 只提交给 192.168.3.21:3081。`
- 选项 1：`直接打开（若本浏览器已解锁）`
- 选项 2：`使用 launch token 解锁`
- 输入 placeholder：`粘贴 launch token（不会显示）`
- 主按钮：`解锁并打开`
- 次按钮：`复制入口地址`
- 帮助：`▸ 如何获取 token（向节点 owner 索取）`
- 安全：`▸ 安全说明：LAN 明文；勿在共享浏览器保存；用完关闭标签`
- 提交后 toast：`已在新标签打开。若仍要求 token，说明 token 无效或已过期。`
- origin 缺失：`该节点未配置入口地址，请检查节点配置。`

#### 7.5.7 P2 改进

1. **节点侧支持 POST `/connect`**：token 放 body，避免 URL/历史/日志；需要 DSH 上游或节点侧薄代理。
2. **本机 helper**：`dsh-open://node/dsh-c`，helper 从 OS 钥匙串取 token 并打开浏览器；面板只传节点 id，不传 token。
3. **HTTPS + 反向代理认证**：面板与节点统一 TLS；面板前置 OIDC/Basic Auth；这会把“无认证 LAN”升级为“有边界”。
4. **每节点独立主机名**：`a.lan`/`b.lan`/`c.lan` 隔离 cookie，解决同机 A/B 串扰。
5. **一次性 token**：节点签发 60s 有效、单次使用的 launch token；用完即废。

### 7.6 复制与导出

- `[复制入口地址]`：复制 `node.origin`，不含 token；toast `已复制入口地址`。
- `[复制任务 ID]`：复制 `task.id`；toast `已复制任务 ID`。
- `[复制诊断]`：复制 JSON：
  ```json
  {
    "generatedAt": "2026-11-20T14:48:26.579Z",
    "node": { "instanceId": "dsh-d", "label": "dsh-d", "role": "agent",
              "origin": "http://192.168.3.24:3081", "online": false,
              "latencyMs": 2500, "error": "timeout" },
  ```

  默认**不包含**任务 summary/cwd（可能含业务信息）；P1 可加“包含任务摘要”复选框并明确提示。

- 不提供“导出全部数据”按钮；原始 `/status` 已可直接访问，避免制造额外泄漏面。

### 7.7 移动端交互

- 单列卡片；卡片动作按钮等宽、44px 高；整卡点击开抽屉。
- 抽屉全屏；顶部固定标题与关闭；tab 横向可滚动（不超过 4 个，不滚动）。
- 筛选使用底部 sheet；状态 chips 两行；搜索框吸顶。
- 拓扑为列表，不做拖拽/缩放。
- token 对话框全屏；输入框 `font-size:16px` 防 iOS 缩放；提示“建议在桌面完成 token 解锁”。
- 下拉刷新不实现（浏览器自带刷新即可）；避免和页面滚动冲突。
- 所有 hover 效果都有 focus/active 等价；不依赖 hover 才能看到信息。

### 7.8 键盘与可访问性

- 语义结构：`header` / `main` / `section` + `aria-labelledby` / `footer`；页面只有一个 `h1`。
- 跳过链接：`跳到节点`、`跳到任务`；聚焦时可见。
- 卡片是 `<article>`，标题是 `<h2>`；整卡点击用内部 `<button class="card-hit">` 覆盖，或卡片 `tabindex=0` + Enter/Space；不要用 `div onclick` 无键盘支持。
- 抽屉 `role="dialog" aria-modal="true"`；打开时焦点到标题；Tab 循环；Esc 关闭；关闭恢复焦点。
- 状态：`aria-label` 包含状态词与数值，如 `dsh-b，在线，延迟 2 毫秒`；不要只读“绿点”。
- 刷新：`aria-live="polite"` 只播报健康级别变化/错误；`aria-busy` 标在刷新按钮/区域；不每 10s 播报。
- 颜色：所有状态有图标/文字；用灰度截图仍可区分。
- 对比度：正文 ≥4.5:1；大字/UI ≥3:1；焦点环 2px + 2px offset，对比 ≥3:1。
- 触控：≥44×44；相邻按钮间距 ≥8px。
- 动效：`prefers-reduced-motion` 关闭脉冲/shimmer/位移；不自动播放声音。
- 表格（如果 P1 加密集视图）：`caption`、`th scope`、排序 `aria-sort`；不要用表布局做页面布局。

## 8. 信息密度与可读性平衡

### 8.1 三个阅读距离

| 距离 | 时间 | 看什么 | 设计手段 |
|---|---|---|---|
| 2 米 | 3 秒 | 整体是否健康 | Header 健康 pill、横幅、健康条、大数字 |
| 60 厘米 | 10 秒 | 哪个节点、什么状态、入口 | 节点卡身份区、状态行、3 个计数 |
| 30 厘米 | 1–2 分钟 | 证据、版本、任务详情 | 抽屉、任务展开、原始 JSON |

### 8.2 六条防“更花的表格”规则

1. **一屏只留一个主角**：第一屏主角是节点卡；拓扑是辅助，不抢卡片。
2. **卡片最多 3 个数字 + 3 个资源占位**：超过就进抽屉；不要把 9 列塞进卡。
3. **一个区块只用一个边框**：不要卡片套卡片；用间距和背景层级分组。
4. **状态不超过 4 种颜色**：绿/琥珀/红/灰蓝；accent 只做交互。
5. **每行只允许一个省略号**：标题省略、cwd 中间省略、URL 省略；不要让三个字段都截断。
6. **空态必须有解释**：`暂无数据` 不合格；要回答“为什么空、是否正常、下一步”。

### 8.3 长内容处理

| 内容 | 卡片 | 任务行 | 抽屉 | 规则 |
|---|---|---|---|---|
| `osRelease` | 不显示 | 不显示 | 默认折叠，显示“展开完整 uname” | 卡片用解析后的 `Ubuntu · x64` |
| hostname | 1 行省略 | 不显示 | 完整 | title 给全量 |
| origin URL | 只显示 `host:port` | 不显示 | 完整可复制 | 不把 `http://` 重复三遍 |
| 任务标题 | 不显示 | 1 行省略 | 完整 | 120 字上限来自后端 |
| 任务 summary | 不显示 | 展开后 6 行 + “全文” | 完整 | 不塞进折叠行 |
| sessionId | 不显示 | 不显示 | mono + 复制 | 卡片只显示计数 |
| cwd | 不显示 | 不显示 | 中间省略 + title | 移动端隐藏 |

### 8.4 四种“没有”必须区分

| 状态 | 视觉 | 文案 | 例子 |
|---|---|---|---|
| 空 | 中性空态图标 | `当前没有活会话` + 解释 | sessions=[] |
| 零 | 正常数字 `0` | `运行任务 0` | running=[] |
| 未知/未采集 | 虚线/`—` | `未采集（P1）` | CPU/内存/磁盘 |
| 失败 | 红色/错误图标 | `无法读取 /status：HTTP 502` | 请求失败 |

**绝不把“未采集”写成 0，也绝不把“空”写成错误。**

### 8.5 卡片 vs 密集表格

- 默认卡片视图：适合 4 个节点、扫读、移动端。
- 提供 `[卡片|表格]` 切换（P1）：表格用于“同屏对比版本/延迟/会话数”，列压缩为 6 列：节点、状态、角色、延迟、会话、运行任务；主机/uname 不进表格。
- 表格必须 `overflow-x:auto` 且首列 sticky；不能像现在这样让页面横向滚动。
- 视图选择写入 `localStorage["lan-status-view"]`；默认卡片。

### 10.2 视觉

### 10.3 安全

- [ ] 面板 HTML/JS/配置中 grep 不到 `token=` 的硬编码值；只有表单字段名与说明文字。

## 11. 风险与开放问题

### 11.1 主要风险

| # | 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|---|
| 1 | token 可用性 vs 安全性 | **高** | 一键打开越顺，token 越容易进历史/密码管理器/截图；太安全则没人用 | 面板零持有；表单直提节点；一次性 token；无痕建议；P2 helper/POST |
| 2 | 数据不诚实/陈旧 | **高** | 绿色可能是 30 秒前；CPU 占位可能被当成 0%；B/C 任务空可能被当成坏了 | 新鲜度/陈旧态；未采集虚线；来源徽标；空态解释 |
| 3 | 入口冒充/钓鱼 | **中高** | 面板无认证，任何人可仿页面骗 token | 明确地址；不要从聊天链接直接粘贴 token；P2 反代认证/TLS |
| 4 | 同机 A/B 混淆 | **中** | 同 hostname、cookie 不按端口隔离、3091/3092 易写错 | 卡片显示端口徽标；配置校验；P2 分域名 |
| 5 | 信息过密/过度设计 | **中** | 4 个节点加太多图表/卡片反而难扫 | 三层结构；卡片只留 9 字段；无图表墙；P0 先做减法 |
| 6 | 只读面板被误当操作台 | **中** | 用户可能期待重启/取消任务 | 抽屉底部“只读，无操作”；不放置灰色按钮 |
| 7 | 手机端 token 流程难用 | **中** | 手机上找 token/粘贴不便 | 手机优先“看”；提示桌面解锁；复制地址降级 |
| 8 | 任务摘要隐私 | **中** | 无认证 LAN 页面可读 summary/cwd | P1 CORS 收紧/鉴权；复制诊断默认不含 summary；文档标注 |

### 11.2 开放问题

1. **token 从哪里获取？** 需要节点 owner 的 runbook；当前文档只给“向 owner 索取一次性 launch URL”，不硬编码不确定的日志命令。P1 应由 owner 补充经过验证的命令。
2. **dsh-d 长期离线是否正常？** 若是预期维护，P1 需要“维护模式”，否则横幅会长期占用注意力。
3. **是否需要每节点台账？** 当前 B/C/D 的 `tasks.total=0` 是设计结果，不是故障；若用户希望看各节点自己的调度，需要 P1 采集并明确“本机台账 ≠ 协调者台账”。
4. **真实 interconnect 拓扑能否采集？** 需要 dsh-interconnect 暴露只读状态；没有就保持“探针拓扑”，不要猜边。
5. **面板是否要加认证？** 当前按立项非目标不做；若跨网段/多人环境，P2 反代认证优先于自研账号。
6. **token 表单是否会被浏览器密码管理器保存？** `autocomplete=new-password` 只能降低概率；需要在 Chrome/Edge/Firefox 实测并写入验收记录。
7. **P0 是否允许改 `server.js` 加安全头？** 建议允许（不改数据契约）；若严格“只改 HTML”，把 CSP/Referrer 放 P0.5，但入口表单的 `form-action` 限制应尽量早做。

### 12.3 Token 获取 runbook（需节点 owner 按部署核实）

> 以下只是**示例**，不同节点的 systemd/计划任务/日志路径不同；不要把未核实的命令写进面板 UI。

```bash
# Linux 示例：从服务日志中找最近一次 launch URL（服务名按实际替换）
journalctl --user -u dsh-lan-c --since "10 min ago" \
  | grep -oE 'https?://[^ ]+token=[A-Za-z0-9._~-]+' | tail -n 1
```

```powershell
# Windows 示例：从日志中找 token（路径按实际替换）
Select-String -Path "$env:USERPROFILE\.dsh\*.log" -Pattern 'token=[A-Za-z0-9._~-]+' |
  Select-Object -Last 1
```

安全要求：

- 只把 token 发给当前值班人，不发群、不进工单截图。
- 优先使用一次性/短期 token；用完关闭节点标签。
- 面板侧不保存；节点侧日志应脱敏或限制读取权限。

### 12.4 术语

| 术语 | 含义 |
|---|---|
| 协调者 / coordinator | dsh-a，聚合 `/status`、读调度台账、提供面板 |
| agent | B/C/D，只暴露 `/self`，不读协调者台账 |
| 探针链路 | 协调者 `GET agentUrl/self` 的可达性/延迟，不是 dsh-interconnect 对等链路 |
| 陈旧 / stale | 数据存在但超过新鲜度阈值；不能继续标绿 |
| 未采集 | 该字段当前没有数据源；不是 0，也不是失败 |
| launch token | DSH Web 的入口令牌；可换 `dsh-auth` cookie；面板不持有 |
