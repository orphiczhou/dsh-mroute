最终拓扑

三台机器、四个独立 DSH web 实例；只有 dsh-a 是 active coordinator。状态面板与免 token 网关是旁路，不改变 DSH 原生 3081 的认证。

04

限制与残留

结案不等于“全部完美”；下面这些项已登记，不阻塞本阶段，但不能当作已完成。

项状态说明
非信任源 403 端到端⚠️ 仅单测本机无第二网段；建议隔离 VLAN 验证
B/C/D dock 视觉⚠️ 未逐台点开包/配置/代理 200；A 与本地已视觉验证
面板认证⚠️ 无只读且不持有 token；LAN 内可访问
网关安全边界⚠️ allowlist=owner只允许直连可信 CIDR；不能公网/反代
Windows 桌面版❌ 未修复host ready URL 303 正常，shell fetch ECONNRESET；已提供 LAN 快捷方式
调度层能力⚠️ 薄层无 DAG/抢占/文件传输/多协调者共享台账
journal/队列上限⚠️ 未做需监控或后续轮转
不要这样部署：把 3095/3096 映射到公网、放在不可信反代后面、或把面板当成有认证的控制面。allowlist 内任意 IP 等价于 owner。
05

下一阶段

按“运营化 → 安全 → 能力”排序；不建议继续在薄层上堆 DAG。

P0运营化：单协调者 + 台账监控▶
A 作为唯一任务入口；B/C/D 只保留 worker 工具面；为 journal/台账加轮转、容量告警与备份；把“任务成功/失败”接入面板 KPI。
P1安全：面板认证 + 非信任 403 实测▶
给面板加最小认证/限流；在隔离 VLAN 做非信任源 403 端到端；如跨不可信网络，再上 TLS/WireGuard。
P2能力：依赖/DAG 与文件清单▶
先做“任务依赖 + 文件清单 + 断点”最小闭环，不要直接做完整工作流引擎；跨机文件传输另走 mesh 或独立通道。
P3Windows 桌面版单独立项▶
抓 shell 侧具体 fetch URL/headers，或等上游修复；当前以 LAN 网关入口为可用替代。
