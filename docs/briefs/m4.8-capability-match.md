## 2. 设计（已定，直接实现）

### 2.1 新输入 `need`（可选）

`model_route_query` 入参新增可选对象 `need`，键闭集 = `['coding','tools','long_context','vision']`，值闭集 = `['fair','good','excellent']`（大小写敏感，非法值 → 参数错误，明确报哪个键/值非法）。

语义：`need.coding = 'good'` 表示「该模型 coding 至少 good」。多个键 = **全部满足**（AND）。`need` 为空对象或省略 = 不做匹配（旧行为完全不变）。

### 2.2 评级序与判定

- 序：`fair(1) < good(2) < excellent(3)`；`'none'` = 0（明确无能力，**不满足任何需求**）；未登记（键缺失）= `null`（未知，**不算满足**，但要单独统计，见 2.4）。
- 判定：对某模型，`need` 中每个键都满足 `ratingOf(model, dim) >= need[dim]` 才算 `match`。
- 档位来源：`registry.model_ratings`（**规范名优先**，其次按渠道模型 id，最后回退旧 `channels[].model_capability` / 渠道级 `capability`），复用 `lib/registry.js` 现有 `ratingsForModel(channel, canonical, modelId, ratingTable)`，**不要另写一套解析**。
- 规范名：`canonicalOf(registry.model_aliases, channelId, modelId)`（现有函数）。

### 2.3 输出（只增不改，advisory-only）

1. `routes[i]` 增两个**可选**键（仅当传了 `need` 才出现）：
   - `matching_models: string[]` —— 该渠道里满足需求的渠道模型 id，排序：综合档位高者优先（按 `need` 各维度分值和降序）→ 渠道 `models[]` 原序兜底；
   - `suggested_model: string | null` —— `matching_models[0]`，无匹配则 `null`。
2. 顶层新增**可选** `model_picks: Array<{canonical, channel_id, channel_model, rank, ratings}>`（仅当传了 `need` 才出现）：
   - 每个有匹配的渠道取 `suggested_model` 一条；
   - 排序：**先按匹配质量降序**（`need` 各维度分值和总和降序，再按最小裕度降序），**同分再按渠道 rank 升序**，最后 `canonical` 字典序兜底 —— 这就实现用户裁决的「先按任务能力选模型，再在这些模型所在渠道里按渠道优先序」；
   - `ratings` 是该模型的四维档位（只放有值的键，`none` 也放）。
3. `meta` 增可选 `capability_need`（原样回显 `need`）与 `unrated_models`（见 2.4）。
4. `models_index[].ratings` 保持不变（已有）；**文本渲染必须补上档位**（当前完全没打印，属缺陷）：形如
   `- glm-5.3-flash [coding:good tools:excellent long_context:good vision:good]: zai-coding-cn→glm-5.3-flash(#1), opencode-go→glm-5.3-flash(#2)`；
   `none` 打印为 `无`。

### 2.4 文本渲染（`renderRouteResult`）

- 传了 `need` 时，头部加一行：`能力需求: coding≥good, vision≥good（advisory：仅标注与推荐落点，不阻断、不改 routes 排序）`。
- 每条 route 加一行（有 `matching_models` 时）：`匹配模型: glm-5.3(excellent), glm-5.3-flash(good)` —— 括号里放该模型在 `need` 涉及维度上的**最低**评级（说明为何满足），最多列 4 个，其余用 `等 N 个`。
- route 无匹配时加：`匹配模型: 无（本渠道没有满足该能力需求的模型）`。
- 结尾新增段（有 `model_picks` 且非空）：
  ```
  能力匹配推荐（先按能力匹配质量，再按渠道排序；advisory，不阻断）:
  1. glm-5.3 @ zai-coding-cn (#1) | coding:excellent tools:excellent long_context:excellent vision:无
  2. ...
  ```
- 统计未登记：`未登记档位: qwen3.8-flash?` —— 不，改为：`档位未登记模型: <N> 个（不计入匹配）`，N = 参与匹配的模型里四维中**至少一维**在 `need` 所涉维度上缺失的个数。
