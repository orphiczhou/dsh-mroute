## 1. 背景（一句话）

`mroute` 是 DSH 的「多子会话模型路由建议」插件：host 半提供三个工具（`model_route_query` / `model_route_sync_models` / `model_route_alias_suggest`），client 半在设置面板注册「模型路由」分区。用户本轮提出两件事：

1. **面板要显示 host 侧算出的动态层状态**——现在「动态沉底（dynamicTight）」「窗口高水位提示（window_high hint）」「低余额」只在工具文本里出现，面板上看不到，用户无法在编辑时判断哪些渠道正处于风险态。
2. **能力维度从 4 维扩到 6 维**：新增 `world_knowledge`（世界知识：模型知识面全面性）、`orchestration`（策划调度：作为指挥官拆解任务、分配调度子会话的能力）。评级闭集不变，仍 `excellent | good | fair | none`。

### 3.2 面板显示动态层（M4.9 核心）

**设计裁决（lead 已定，不要再改方案）**：client 拿不到 host 实时数据（桌面端 origin 是 `dsh-app://app`，相对/绝对 `fetch` 都打不到宿主），所以采用**「最近一次查询快照」**方案：

1. `lib/config-schema.js` 顶层新增 volatile 字段（放在 `model_ratings` 之后）：
   ```js
   dynamic_snapshot: z.object({
     as_of: z.string().default(''),        // ISO 时间
     rows: z.array(z.object({
       id: z.string(),                      // 渠道 id
       state: z.string().default('ok'),     // 'ok' | 'hint' | 'tight'
       reason: z.string().default(''),      // 人读原因，如「本周窗口 98.5%（≥98% 沉底）」
       windows: z.string().default(''),     // 紧凑窗口显示，如 '5h 10% · 本周 21% · 本月 10%'
       worst_used_pct: z.number().default(-1),
       low_balance: z.boolean().default(false),
       display: z.string().default(''),     // 金额型余额显示，如 '¥29.3'
     })).default([]),
   }).default({}).volatile()
   ```
   **注意**：`channels[]` 元素内禁 `.volatile()`（已知坑），而这是顶层固定路径字段，属于合法形态；但**必须先写 schemastery 探针验证**（见 §3.4）。
2. `lib/dynamic-state.js` 新增纯函数 `buildDynamicSnapshot(routes, asOf)`（输入就是 query 已经算好的 routes，含 `dynamic`/`balance`），输出上面那个形状；不新增任何 IO。
3. `lib/tool-query.js`：在 `model_route_query` 组装完结果后，尝试写回快照：
   - 条件：`snapshotChanged`（与当前 config 里的 `dynamic_snapshot.rows` 深比较不同）或 `as_of` 距现在超过 30s；
   - 写法：与 `tool-sync-models.js:243-259` 同款（`ctx.fiber.entry` + `ctx.get('configEditor').edit(entry, current => ({...current, dynamic_snapshot: next}))`），**全程 try/catch 静默失败**，绝不影响查询结果；
   - 写失败只在 `meta.dynamic_snapshot_error` 里留一句人读原因（可选键，不破坏既有输出）；
   - **不改变** `routes[]` 顺序/键、不改 `need` 相关键的缺失性、不新增顶层输出键（`meta` 里允许加可选字段）。
4. `client.js`：
   - `formFromView` 读入 `dynamic_snapshot`（只读，**不要**放进 `buildSaveOps`，也不要被保存路径清空）；
   - 渠道卡 chips 区增加动态 chip：`tight` → `⚠ {reason}`（warn 色）、`hint` → `{reason}`（idle/hint 色）、`low_balance` → `{display} 低余额`；无快照行则不加 chip（零噪音）；
   - 顶部（建议顺序卡附近）加一行只读摘要：`动态层（as_of …）· 沉底 N · 提示 M`，无数据时显示「暂无动态数据：在会话里执行一次 model_route_query 后回到本页」；
   - 所有新文案走 i18n `zh`/`en` 双语（`bi()` 或现有 label 机制）；新 class 一律 `mroute-` 前缀，只用 theme token。
5. 自检：
   - host 单测：`buildDynamicSnapshot` 的 tight/hint/ok/低余额四态与「无 machine 数据 → ok」；
   - client 单测：假 `dynamic_snapshot` 注入后 chips 文案出现、保存 ops 里**不含** `dynamic_snapshot`；
   - 现有 121 个用例全部仍绿。

## 4. 环境坑（必读，别踩）

1. **宿主工具 schema 禁 type 数组**：`ctx.tools.register` 的 schema 只接受单一 `type` 字符串（`type: ['string','null']` → `unsupported JSON schema … type arrays are not supported`，且失败只落 `logger.error`，**整套工具一个都注册不上而 fiber 仍 active**）。可空字段 = 声明单一 type + 无值时不发该键（见 `docs/05-m3-devlog.md` §16.7）。
2. **schemastery 规则**：`channels[]` 元素内禁 `.volatile()`（调用期抛 fixed-path 错）；`channels` 数组整体 volatile 合法；顶层固定路径字段 volatile 合法；`z.record` 不存在、`z.dict` 存在。
3. **PowerShell 5.1**：`Set-Content -Encoding UTF8` 会写 BOM → `set_bundle` 报 `Unexpected token '﻿'`。改 JSON 一律 `node -e "…fs.writeFileSync(p, JSON.stringify(j,null,2)+'\n','utf8')"`；改源码/文档用编辑工具，别用 PowerShell 拼中文。
4. **client 模块热重载**：`plugin_manager action=set_bundle` 关→开即生效，**不需要刷新页面**；但若 `client.js` 有语法错误，旧实例会继续跑并可能写旧 DOM——改完必须先 `node --check`。
5. **client 半约束**：只允许 `require('react')`；样式只用 theme token 与 `mroute-` 前缀类名；`ctx.remote.settings.describe()` 返回 `{ok, value}` 信封，必须 `unwrapResult`（已有工具函数）；面板保存走 `settings.mutate(NS, ops, revision)`。
6. **advisory-only 红线**：不得阻断/改写会话路由；动态层只能**标注**；`enforce_gate` 保持 opt-in 默认关。
7. **不动排序键**、不改 `routes[]` 的形状、不新增顶层输出键（`meta` 内可选键除外）、不新增出站请求。
