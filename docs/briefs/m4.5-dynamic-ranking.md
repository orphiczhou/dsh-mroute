## 1. 背景与用户裁决（原文，2026-11-20）

用户对动态数据是否能影响排序的裁决原文：

> 「动态数据要能影响排序，有的渠道都快没有额度了，再派长程任务，会执行到中间断开的，影响执行。」

以及阈值裁决原文：

> 「5h提示95%即可，周的98%之前都不太会影响任务执行。」

另外两条相关裁决：

> 「模型档位不影响渠道推荐，同一个模型在不同的渠道，优先顺序按渠道优先级排序。」
> 「未核实渠道默认隐藏。」

**本任务只做「动态数据影响排序」这一件**（模型级档位仍不参与排序；未核实渠道行为已实现，不改）。

## 2. 现状（改动前，已实测）

- 余额视图：`lib/quota-view.js` `platformViewOf` 已产出 `mode='window'` + `windows[{label,used_pct,text}]` + `worst_used_pct`；`mode='amount'` 时 `balance` 为数值。

- 面板：`client.js` 渠道卡 chips（`mroute-chip`）、顶层参数卡（`low_balance_threshold_cny` / `quota_cache_ttl_seconds`）。

## 3. 交付规格

### 3.1 动态状态判定（新模块 `lib/dynamic-state.js`）

纯函数，输入（渠道 + machine 余额视图 + 阈值），输出：

```js
{ state: 'tight' | 'hint' | 'ok', reasons: string[], metrics: { week_pct?:number, h5_pct?:number, balance?:number } }
```

规则（**按用户裁决，不要自己加码**）：

| 条件 | 状态 | 说明 |
|---|---|---|
| 周窗口 `已用% ≥ window_week_tight_pct`（默认 98） | `tight` | 沉底 |
| 金额型余额（CNY）`< low_balance_threshold_cny`（沿用既有默认 10） | `tight` | 沉底（「快没额度了」） |
| 5h 窗口 `已用% ≥ window_5h_hint_pct`（默认 95） | `hint` | **只标注不沉底** |
| 其余 / 无 machine 数据 | `ok` | 无噪音 |

细节要求：

1. **绝不臆造**：无 machine 视图、`mode=status`、窗口项缺失 → 该条规则不触发，`reasons` 不写。
2. 多条同时命中：`tight` 优先级高于 `hint`，`reasons` 全列（如「本周窗口 98%（≥98% 沉底）」「余额 ¥6.20 低于阈值 ¥10」）。
3. 金额型只在 `currency === 'CNY'` 或 `currency == null` 时比较阈值（USD 不臆测汇率，理由同 `tool-query.js:124-131` 现有口径）。

### 3.2 排序接入（`lib/ranking.js`）

- 全序键在 **livecheck unknown 与 channel_type 之间**插入一档：`dynamicTight`（tight=1、否则 0）。
- `rankChannels(channels, livecheckById, dynamicById)`：第三参可选（缺省 `undefined` → 全部按 ok 处理，保持既有调用与测试不破）。
- `reasonFor` 增加一条：`动态紧张 → 沉底（<reasons 拼接>）`；`hint` 不写进排序理由（避免噪音），只进 `route.dynamic`。
- **红线**：tight 只改变推荐顺序，**不剔除、不阻断**（仍出现在 routes[] 里，`excluded` 不变）。

### 3.3 输出契约（`lib/tool-query.js`）

1. `routes[]` 新增可选键 `dynamic: {state, reasons[], metrics{}}`（`ok` 时也带 `state:'ok'`，但 `reasons` 空数组；保持消费方分支简单）。
2. 文本渲染：tight 行首不变（⚠ 已有），在 `备注:` 之前加一行
   `   ⚠ 动态沉底: 本周窗口 98%（≥98%）；余额 ¥6.20 低于阈值 ¥10（不阻断）`
   hint 行加 `   · 提示: 5h 窗口 96%（≥95%，不沉底）`（用 `·` 轻量前缀，不要 ⚠）。
3. `output.schema` 同步（`dynamic` 对象，`additionalProperties:false`）。
4. `meta` 增加 `dynamic_thresholds: {window_week_tight_pct, window_5h_hint_pct, low_balance_cny}`，便于复盘。

### 3.4 配置（`lib/config-schema.js`）

新增两个顶层 `.volatile()` 字段（**只增不改**，与既有 `low_balance_threshold_cny` 同形）：

- `window_week_tight_pct`: number，默认 98，范围 1–100，整数；
- `window_5h_hint_pct`: number，默认 95，范围 1–100，整数。

面板顶层参数卡补两个输入（i18n zh/en 双语，标签走既有 `bi()`；zh：「周窗口沉底阈值」「5h 提示阈值」）。

### 3.5 面板（`client.js`）

- 渠道卡 chips 增一枚动态 chip：`tight` → 「额度紧张」(`is-warn`)、`hint` → 「5h 偏高」(`is-idle`)、`ok` → 不显示。
- 折叠态即可见（chips 本来就在折叠态渲染）。
- **不要**新增按钮/请求；数据来自 host 输出——注意：面板当前不消费 `model_route_query` 的输出（它只读 settings），所以 chips 只能基于**注册表字段**（如 manual/quota_account_verified）计算，**不能拿到实时窗口百分比**。→ 因此本任务面板只做一项：把两个新阈值字段加进顶层参数卡。动态 chip 留到下轮（面板若能拿到 host 数据再加），**不要**为此新增请求通道。

### 3.6 自检（`selfcheck/`）

新增 `selfcheck/dynamic.test.mjs`（node:test）：

1. 周 98/97.9 边界、5h 95/94.9 边界各一对；
2. 金额阈值 CNY / USD / null 币种三态；

4. 无 machine 视图 → `ok` 且 `reasons` 空；
5. `rankChannels` 三参新键：构造两渠道，tight 的沉到后面；缺省第三参时顺序与旧版一致（回归）；
6. `renderRouteResult` 文本包含/不包含新行（tight 有、hint 有 `· 提示:`、ok 都没有）。
