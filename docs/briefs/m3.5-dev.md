## 1. 背景

`D:\Codes\DSH小插件\plugin-mroute` 是 DSH 插件（当前版本 `0.4.0-m3.0`），提供：
- host 侧工具 `model_route_query`：按注册表（channels）算派遣优先建议（advisory-only，绝不阻断/改写）；
- client 侧设置面板：在 DSH 设置里注册「模型路由」分区（`settings.section`，id `model-route`，order 18），编辑注册表并保存（走 `ctx.remote.settings` 的 describe/mutate，**返回 `{ok,value}` 信封，必须 `unwrapResult` 解包**）。

用户（2026-11-16）提三条新需求，本轮做前两条，第三条只留占位说明：

1. 面板里看不到「最终的多模型使用优先建议」的链路/结构 → **加只读预览**；
2. 每个渠道下有多个模型，但只能设渠道级能力档位 → **加每模型能力档位**；
3. 自动评价能力档位的界面 → 本轮**不做**（M5 评测层，只在 UI/文档留占位说明）。

## 3. 交付物

### 3.1 面板「建议顺序（静态层）」只读预览

- 位置：`ModelRouteSection` 里、advisory 横幅之后、渠道卡之前，渲染成一张卡片（`section.mroute-card`，可复用现有类名，或新增 `.mroute-preview`）。
- 内容：按**当前表单里的 channels**（未保存也实时反映）算出顺序，每条一行：`#rank  id  ·  channel_type  ·  tier  ·  priority N` + 一句理由。
- 算法：client 内新增纯函数 `previewRanking(channels)`，实现与 `lib/ranking.js` 相同比较器（**忽略 livecheck**，即 unknown 恒 0）。必须 `export` 到 `__mroute` 以便对拍。
- 顶部固定说明（诚实边界，用 `text.previewHint` 词条）：`静态层排序：不含 provider 活校验、余额与 disabled/low_balance 告警；完整链路以 host 工具 model_route_query 为准。`
- 空注册表 → 显示「无渠道」而非空白。

### 3.2 每模型能力档位

- **schema（config-schema.js）**：渠道新增
  ```js
  model_capability: z.array(z.object({
    model: z.string(),
    coding: z.union([...CAPABILITY_RATINGS]),
    tools: z.union([...CAPABILITY_RATINGS]),
    long_context: z.union([...CAPABILITY_RATINGS]),
    vision: z.union([...CAPABILITY_RATINGS]),
  })).default([]).volatile(),
  ```
  说明：四维键在 schemastery object 里「缺键=无数据」，允许省略；数组整体 `.volatile()`（M3 spike 已验证数组 volatile 合法且可写）；旧数据无此键 → 默认 `[]`。
- **registry.js**：读侧归一化（未知模型引用只 warn 不拒）、去重、评级闭集校验；新增 `modelCapabilityOf(channel, model)` 返回 `{coding?,tools?,long_context?,vision?}` 或 `undefined`。
- **面板（client.js）**：展开卡里 `models` 列表区改成「模型行」：模型 id（只读文本）+ 4 个紧凑下拉（`coding`/`tools`/`long_context`/`vision`），选项 = `未登记` + `excellent/good/fair`（用 `bi()` 造中英标签：`优秀 · excellent` 等）。选「未登记」= 删除该维度键；整行四维都空 → 从 `model_capability` 删除该 model 条目。
- **保存链**：`model_capability` 在渠道对象内，**随 `channels` 数组整替一起走，不新增顶层 op**（保存 ops 仍是 `channels` + 三个顶层参数，见 `buildSaveOps`）。
- **客户端轻校验（保存前）**：`model_capability[].model` 必须非空、去重（重复 → 报错并阻止保存，用 `text.saveErrors` 现有机制）；引用不在 `models[]` 里的模型 → **仅提示不阻断**（advisory-only）。
- **工具透出（tool-query.js）**：`routes[]` 增加可选键 `model_capability`（数组原样透出；空数组/未登记则不出现该键）；文本渲染有数据时追加一行 `模型档位: glm-4.6 coding=excellent …`。**排序逻辑一行都不要改**。

## 4. 红线（违反即打回）

1. **advisory-only**：预览、评级、校验都不阻断会话选型、不改写请求、不做 tools.guard deny。
2. 排序全序键不变（channel_type → tier → priority → id）；模型级评级**不得**参与排序，只做标注/透出。
3. client 只用 theme tokens（禁止硬编码色值）、类名 `mroute-` 前缀、只 `require('react')`（不新增依赖、不 import 宿主内部模块）。
4. host 不新增出站网络请求；不读写密钥；不新增工具。
5. 不碰工作区其它项目（`gemini-eyes/`、`plugin-quota-multi/`）。

## 5. 环境事实与坑（必读）

- **改 client.js 后光点导航不生效**：client 模块由宿主 `dsh-client-modules` 按 `artifactRevision(stat)`（mtime/ctime/size 的 sha1 前 12 位）编译分发。改完必须：
  1. `plugin_manager action=set_bundle target=@local/dsh-plugin-mroute enabled:false` → 再 `enabled:true`（两轮都应是 `application:"applied"`；这是本 build 可靠热重载，**不要**用 install_bundle，它走 pnpm 且有中文路径清空源目录的旧事故）；
  2. 用户刷新页面（`Ctrl+Shift+R`）才换到新 rev。
- **验证分发内容**（不要靠猜）：`node C:\Users\sir_c\AppData\Local\Temp\mroute-fetch-bundle.mjs` 会打印 `path/stat/rev/status/bytes` 与若干标记位；再用 `Invoke-WebRequest "http://127.0.0.1:55095/plugins/??@local/dsh-plugin-mroute/client.js&rev=<rev>"` 取回内容，`$_.Content.Contains('标记')` 验证新代码已分发。
- **文件编码坑**：Windows PowerShell 5.1 的 `Get-Content`/`Set-Content` 会按 GBK 解码 UTF-8，破坏中文（曾出现 `涓存椂鎺㈤拡`）。改文件一律用本会话的 `read`/`edit`/`write` 工具或 node 脚本，**不要**用 PowerShell 管道写中文文件。
- 自检命令：`cd D:\Codes\DSH小插件\plugin-mroute; npm.cmd run selfcheck`（基线 60 条，全部通过；`npm.ps1` 被 ExecutionPolicy 挡，必须用 `npm.cmd`）。
- `node --check client.js` 只查语法；`client.test.mjs` 用 `node:vm` 加载 client.js，**任何语法错误都会让 6 组 client 用例全挂**。
- 面板可用的主题 token 已有：`--dsw-alias-bg-overlay`（弹层底）、`--dsw-alias-label-primary`、`--dsw-alias-bg-layer-2`、`--dsw-alias-brand-primary`、`--dsw-alias-state-success-primary`、`--dsw-alias-state-warn-primary`、`--dsw-alias-border-l1/l2`。
