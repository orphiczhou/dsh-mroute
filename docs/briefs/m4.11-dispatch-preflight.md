# M4.11 任务书：派发预检工具（mroute_dispatch_plan）

> 用户裁决（2026-11-20 21:1x）：「A+B：流程纪律 + 预检工具」。A 由 lead 直接落地（AGENTS §1 派发纪律 + 任务书模板），本任务书只覆盖 B。
> 版本目标：`0.8.2-m4.11`。基线：`plugin-mroute` 0.8.1-m4.9.1，`npm.cmd run selfcheck` 128/128 全绿。

## 1. 背景与要解决的问题

mroute 已有全局 systemPrompt 提示（`lib/prompt-section.js:12-14`）：「派遣子会话前先调用 model_route_query…」。但 `model_route_query` 的输出是**完整诊断表**（routes 五行 + 余额 + 归并视图 + 告警），要从中手抄出「provider/model 该填什么」需要模型自己再算一遍，摩擦大、容易跳过。

目标：给一个**意图明确、输出可直接粘贴进 assignee** 的预检工具，降低调用成本（从而提升「派发前先查」的触发率）。

## 2. 环境事实（必读，别踩）

- 工具注册是全局的（`index.js:89-105`，无 scope 参数），子会话也能看到；`systemPrompt.section` 同样全局。
- 宿主工具 schema **禁 type 数组**（`type: ['string','null']` 会让整套工具注册被拒且只落 logger.error）——可空字段就「无值不发该键」。
- `channels[]` 元素内**禁 `.volatile()`**（调用期抛 `require a fixed object path`）；顶层对象/数组整体 volatile 合法。
- 查询走 `getQuota` → quota 插件 HTTP 快照（60s 缓存、熔断）、`livecheck`（provider 活校验）。**不要新增任何出站请求**。
- 排序全序键（`lib/ranking.js`）：`unknown(活校验失败) → dynamicTight(沉底) → channel_type(monthly<voucher<prepaid) → tier(overseas_sota<domestic_sota<bulk) → priority 降序 → id`。
- 改完 `client.js`/`lib/*` 后：`node --check` → `npm.cmd run selfcheck` → `plugin_manager set_bundle` 关→开（热重载，无需刷新页面）。
- `package.json` 只许用 node 重写（PS 5.1 `Set-Content -Encoding UTF8` 会写 BOM，`set_bundle` 直接报 `Unexpected token '﻿'`）。
- 不要在 `client.js` 里 `require` 除 `react` 以外的东西；client 只用 theme token 与 `mroute-` 前缀。

## 3. 交付物

### 3.1 新工具 `mroute_dispatch_plan`（核心）

新文件 `plugin-mroute/lib/tool-dispatch-plan.js`，导出 `createDispatchPlanTool({ ctx, getRegistry, livecheck, getQuota, readConfigValue, logger })`，在 `index.js` 里与现有三个工具同款注册（`ctx.tools.register` + `ctx.effect`）。

**入参**（JSON schema，全部单一 type）：
- `need`：可选对象，键闭集 `coding|tools|long_context|vision|world_knowledge|orchestration`，值闭集 `fair|good|excellent`（AND 语义）。非法时**在 IO 之前**报与 query 工具一致的文案风格：`need 参数非法：键 "x" 的值 "y" 非法（允许 excellent|good|fair，大小写敏感）`。
- `limit`：可选整数 1..10，默认 5。
- `channel_type`：可选，闭集 `monthly|voucher|prepaid`（只筛该付费类型；不给则全给）。

**输出**（`content` 文本为主，另给结构化 `output`）：
```
派发预检 · dispatch preflight（2026-11-20T13:05:12Z）
数据：quota 快照 2026-11-20T12:58:03Z · 新鲜（≤5 分钟）· 5/5 渠道机读可用
需求：coding≥excellent, world_knowledge≥good

1. zai-coding-cn / glm-5.3        [monthly · domestic_sota · priority 80]  🌕 5h 25% · 本周 10%   fit=3 min=3
2. opencode-go / qwen3.8-flash    [monthly · bulk · priority 60]          🌓 5h 20% · 本周 24% · 本月 12%  fit=3 min=2
3. deepseek-official / deepseek-v4-pro  [voucher · overseas_sota · priority 70]  💰 ¥28.90  ⚠ 无匹配（vision:无）

用法：按顺序把 provider/model 填进 subagent/tree_dispatch 的 assignee；被宿主策略门拒绝就换下一项；全被拒则省略 assignee 继承父路由。
标记：🌕=运行态正常　🌓=有窗口告警（沉底/提示见理由）　💰=金额型　⚠=需注意（无匹配/未核实/数据非机读）
```

规则细节：
- 每行 = 一个渠道 + 一个模型。有 `need` 时模型取该渠道的 `suggested_model`；无匹配则写 `—` 并在行尾给 `⚠ 无匹配（<缺的维度>:无/未登记）`。无 `need` 时取 `models[0]`，无模型写 `（模型未登记）`（仍然可用：assignee 可只填 provider？**不可**，所以这种情况要在行尾标 `⚠ 该渠道 models 为空，assignee 需人工补 model 或先跑 model_route_sync_models`）。
- 复用而非复制：优先 import `lib/ranking.js` / `lib/capability-need.js` / `lib/quota-view.js` / `lib/registry.js` 的现成函数；`model_route_query` 里已有的装配逻辑（构建 routes + 余额 + 动态状态）应抽成共享函数（放 `lib/route-build.js` 或 `tool-query.js` 内导出），**两处调用同一份实现**，避免口径漂移。
- 新鲜度：`queried_at` 用本次调用时间；快照时间取 quota 快照自身的 `refreshedAt`/`as_of`（已有字段），差值 ≤300s 记「新鲜」，否则「偏旧（>5 分钟，建议重查）」。熔断/降级/未核实渠道要在行尾 `⚠` 并保留 `manual`/`degraded` 字样——**不要伪造数值**。
- 输出必须**包含 provider 与 model 两个字段的字面值**（这是让模型能直接抄的关键）。
- 结构化 `output`：`{ queried_at, snapshot_at, freshness_seconds, channels: [{ rank, provider, model, channel_type, tier, priority, display, state, reason?, fit?, min?, warnings: [] }], need?, notes: [] }`。
- `content` 长度上限：`limit` 行 + 3 行头 + 2 行脚，不要输出完整诊断表（那是 query 的职责）。
